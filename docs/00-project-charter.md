# 00 · 项目章程

## 1. 背景

2026-11-07/08 的两轮调研结论：

1. 第一轮：调研「视频字幕生成 + 翻译」的开源方案，得出六层流水线与端到端项目对比（`01`）。
2. 第二轮：用户收紧约束后重新分析，确定不用现成 GUI 项目，改为自建薄编排层（`02`）。
3. 本仓库是第三轮产物：把上述结论固化成可交接的设计文档，供后续独立项目会话实现。

## 2. 一句话定义

**CueLoom 是一个字幕生成与翻译流水线：输入视频/音频，输出带翻译的 SRT / VTT / ASS 字幕文件。默认通过零构建的浏览器 Web 工作台操作，命令行与 Python API 可独立跑完整流程。**

> 2026-11-09 修订（U-11~U-13 / ADR-014）：原定义「命令行优先」改为「浏览器工作台为默认操作面」。CLI 仍是一等公民，但不再是默认交互方式；见 `12 §1`。

## 3. 用户明确的约束（原话要点）

| 编号 | 约束 | 对设计的影响 |
|---|---|---|
| C-1 | 不考虑根据视频角色配音 | 移除全部 TTS / 声音克隆 / 说话人分轨 / 音频时长对齐逻辑 |
| C-2 | 最后只生成字幕文件，不烧录 | 不需要 FFmpeg libass、视频合成、mux、编码参数；输出是纯文本 |
| C-3 | 用户能自行提供 LLM 服务 | 翻译层只需一个 OpenAI 兼容客户端；不集成第三方翻译 API，不内置本地小模型作为默认 |
| C-4 | 稍后删除本会话、另开项目会话 | 文档必须自包含，见 `docs/README.md` |

推导约束：
- C-5：Python 环境用 `uv` 在项目目录管理（用户跨项目长期约定）。
- C-6：CLI 优先，服务化只包一层（自建路线的既定决策，见 `07` ADR-006）。**2026-11-09 局部修订**：`pipeline.py` 与传输层解耦、服务层不写业务逻辑两条继续有效；「CLI 是默认交互方式」由 ADR-014 取代，浏览器工作台成为默认操作面，CLI 保持可独立运行。

## 4. 目标（In Scope）

- G-1 从本地视频/音频文件生成源语言字幕，时间码精确到词级对齐后的帧内量级。
- G-2 用自有 LLM 服务把源语言字幕翻译成目标语言，保持术语一致、上下文连贯。
- G-3 输出单语或双语（同一 cue 内两行）的 SRT / VTT / ASS 文件。
- G-4 每阶段产物落盘 JSONL，支持断点续跑、单阶段重跑、A/B 对比。
- G-5 输出前自动质检：时间码、阅读速度、术语、数字、cue 覆盖率。
- G-6 CLI 与 Python API 可用；FastAPI 作为薄封装，提供 `/api/*` 状态与写接口（写操作经命令层，见 `12 §4`）。
- G-7 `./ctl.sh` 交互式菜单管理服务生命周期（启停 / 状态 / 日志 / 初始化 / Docker）并作 CLI 兜底；**零构建浏览器 Web 工作台**统一承载工作流运行、配置修改、模型管理与 API 管理（U-11~U-13，详见 `12`）；支持 Docker 部署（详见 `09`）。

## 5. 非目标（Out of Scope，一期明确不做）

- N-1 TTS、配音、声音克隆、多角色分轨、BGM 混合、语速对齐。
- N-2 硬字幕烧录、软字幕封装、音视频合成、转码、画面裁切。
- N-3 yt-dlp / 在线视频下载、平台账号与 cookie。
- N-4 桌面 GUI、Streamlit / Gradio / 前端框架、npm / Node / Vite / CDN 与任何构建工具一律不引入；**例外**：允许由 FastAPI 托管的零构建原生静态 Web 工作台（≤3 个静态文件，见 `12 §5`、ADR-014），可读写，但不编辑字幕内容、不承载业务逻辑（逻辑归命令层与 `pipeline.py`）。
- N-5 已有硬字幕的 OCR 识别（如确需，另用 Subtitle Edit 人工处理）。
- N-6 多租户、**账号体系 / 用户鉴权**、计费、分布式队列（一期）。注：ADR-016 的回环强制、Origin/CSRF 校验与可选本地令牌属于单机防跨站最小防护，不属于账号体系，不在排除之列。
- N-7 自研 ASR / 训练模型、微调翻译模型。
- N-8 说话人分离（diarization）；若将来要做，作为独立可选 stage。

## 6. 成功标准（初始目标，需在 M2 用实测校准）

| 维度 | 指标 | 初始门槛 |
|---|---|---|
| 转写 | 中文 CER / 英文 WER | 在自建测试集上不劣于 faster-whisper large-v3 基线 |
| 时间码 | 词级对齐误差 | 相对强制对齐结果，边界偏差中位数 < 100 ms |
| 断句 | CPS 达标率 | ≥ 95% 的 cue 落在 12–17 字/秒（中文） |
| 翻译 | 术语一致率 | ≥ 98%（术语表内词条） |
| 翻译 | 数字 / 否定保留率 | 100%（质检规则可拦截） |
| 工程 | cue 覆盖率 | 100%，无丢句、无重叠、无零时长 |
| 工程 | 时间码不可变性 | 翻译前后 SRT 的起止时间完全一致（自动断言） |
| 成本 | 单 10 分钟视频 LLM token | 可估算、可缓存、可复盘（具体上限待 D-06） |

## 7. 术语表

| 术语 | 含义 |
|---|---|
| cue | 一条字幕，含 id、start、end、text；SRT 中的一个序号块 |
| word | 词级对齐结果，含 text、start、end、confidence |
| ASR | 自动语音识别 |
| VAD | 语音活动检测，用于切掉静音、抑制幻觉 |
| forced alignment | 强制对齐：用音素/CTC 模型把已知文本对齐回音频，得到精确词级时间 |
| CPS | characters per second，字幕阅读速度指标 |
| glossary | 术语表，源语言词 → 目标语言固定译法 |
| JSONL | 每行一个 JSON 对象的中间产物格式 |
| reflection pass | 翻译后的二次自检/润色轮次 |
| bilingual cue | 同一 cue 内 `原文\n译文` 两行，共用一条时间轴 |
| hallucination | ASR 在无语音段编造出文本 |
| CER / WER | 字错率 / 词错率 |

## 8. 输入 / 输出契约

- 输入：本地文件路径（`.mp4 / .mkv / .mov / .wav / .mp3 / .m4a` 等）；M1 不接 URL。浏览器入口一期只接受上传到项目内 `inbox/`（gitignore）或内置演示素材，不接受任意宿主机绝对路径（`12 §7`）。
- 语言：源语言可自动检测或 `--from` 指定；目标语言 `--to` 必填（一期单目标语言）。
- 输出目录：`out/<job_id>/`，含最终字幕与各阶段 JSONL；最终字幕同时软链/复制到用户 `--out` 指定位置。
- 产物只有字幕文件（`*.srt / *.vtt / *.ass`），**不产出任何视频或音频文件**（音频抽取的中间 wav 视为可再生中间产物，位于 `work/`）。

## 9. 环境与运行约定

- Python 3.11+；依赖用 `uv` 管理：`uv sync`、`uv run cueloom ...`。
- 服务统一由 `./ctl.sh` 菜单启停（不传复杂参数）；启动后通过浏览器工作台操作业务；环境变量集中放 `.env`（由 `.env.example` 复制，不入库，也可由工作台表单写入，见 `12 §8`）；详见 `09` / `12`。
- 不做全局 pip 安装；不引入 conda。
- 模型权重放项目内 `models/`（已 gitignore），**不放 `~/.cache/huggingface` 等系统目录**；首次运行按需下载并校验完整性。模型资产布局与「查看 / 下载 / 删除」工作台见 `10`（U-7~U-10，2026-11-09 追加，代码待 M0.6）。
- 密钥只从环境变量或 `configs/local.yaml`（已 gitignore）读取，不写进代码或文档。
- 日志默认 INFO，可用 `--verbose` 打开 DEBUG；日志中禁止打印完整字幕正文与 API key。
