# 06 · 质量指标、测试与回归

## 1. 指标体系

| 层 | 指标 | 定义 | 采集方式 |
|---|---|---|---|
| ASR | CER（中）/ WER（英） | 与金标准转写比对 | 测试集脚本 |
| ASR | 幻觉率 | 命中黑名单或人工判定的编造段 / 总段数 | 规则 + 人工抽检 |
| ASR | 语言识别准确率 | 正确语种 / 样本数 | 测试集 |
| 对齐 | 边界偏差中位数 | 与强制对齐参考值比较 | 单测 + 抽检 |
| 断句 | CPS 达标率 | 落在 12–17 字/秒的 cue 占比 | `qc` 规则 |
| 断句 | 语义完整率 | 人工判定未从中间切断语义的 cue 占比 | 人工抽检 50 条 |
| 断句 | 禁切违规数 | 数字/术语被拆开的次数 | 规则，应为 0 |
| 翻译 | 术语一致率 | 术语表词条按约定译出的比例 | 规则 |
| 翻译 | 数字 / 否定保留率 | 正确保留的比例 | 规则 + 抽检 |
| 翻译 | 人工评分 | 准确性 / 术语 / 简洁度 / 口语化，1–5 分 | 每批抽样 10 条 |
| 工程 | cue 覆盖率 | 输出 cue 数 / `20_cues.jsonl` 数 | 自动断言 100% |
| 工程 | 时间码不可变性 | 翻译前后 start/end 完全一致 | 自动断言 |
| 工程 | 缓存命中率 | 命中 cue 数 / 总 cue 数 | 运行摘要 |
| 工程 | 耗时与 token | 每阶段耗时、LLM token | 运行摘要 |

## 2. 验收门槛（初始目标，M2 校准后固定）

| 指标 | 门槛 | 级别 |
|---|---|---|
| cue 覆盖率 | 100% | 硬门槛，CI 断言 |
| 时间码不可变性 | 完全一致 | 硬门槛，CI 断言 |
| 禁切违规 / 时间重叠 / 零时长 / 丢句 | 0 | 硬门槛 |
| 数字与否定保留 | 100% | 硬门槛 |
| 术语一致率 | ≥ 98% | 目标 |
| CPS 达标率 | ≥ 95% | 目标 |
| ASR CER | 不劣于 faster-whisper large-v3 基线 | 目标 |
| 人工评分均值 | ≥ 4.0 / 5 | 目标 |
| error 级质检问题 | 0（允许 warn） | 发布门槛 |

注意：`01 §7` 指出的外部数据（如幻觉 183→22→4、中文 CER 7.81%）**只能作为动机，不能直接当验收数字**，必须在本项目测试集复现。

## 3. 测试集设计

准备 5 类各 1–2 段、每段 30–60 秒的代表性音频 + 金标准 SRT（人工校对）：

| 编号 | 类型 | 考察点 |
|---|---|---|
| T1 | 清晰普通话 / 英语口播 | 基线 CER、常规断句 |
| T2 | 带口音、方言或中英混说 | ASR 后端切换价值 |
| T3 | 背景音乐 / 噪声 / 长静音 | VAD 与幻觉抑制 |
| T4 | 专有名词、数字、代码术语密集 | 术语表与数字保留 |
| T5 | 两人对话、语速快、抢话 | 断句与时间码（不做 diarization，只考察不丢句） |

- 音频与金标准字幕体量较大，建议放 `tests/fixtures/` 但用 Git LFS 或外链说明；**不要把大二进制直接提交**。
- 每段配一份 `meta.json`：来源、语言、时长、是否授权、已知难点。
- 版权：只使用自有或明确可再分发的素材；翻译他人正片再分发需授权，工具开源不改变这一点。

## 4. 基线对照组（必须建立）

用 **VideoLingo 纯字幕模式**（关闭 dubbing / 纯字幕精简版，接同一个自有 LLM 端点）对同一 T1–T5 跑一遍，把输出 SRT 存为 `tests/baseline/videolingo/`。

用途：
1. 断句质量的直观参照（它的语义断句 + 术语表 + 反思润色是当前开源侧较好的实现）。
2. 译文风格与人工评分的对照。
3. 防止自建版本在「质量」上悄悄退化。

基线只作为对照，**不复制其代码**（许可虽为 Apache-2.0，但本项目设计是独立实现）。

## 5. 测试分层

```
tests/unit/
  test_segment.py        # CPS、禁切、行尾虚词、cue.id 稳定、时间码单调
  test_qc.py             # 每条规则的触发与自动修复
  test_llm_schema.py     # id 集合、缺项、空文本、围栏剥离、数字比对
  test_cache.py          # key 版本化、命中、失效
  test_subtitle_io.py    # SRT/VTT/ASS 读回一致、双语两行、毫秒精度
tests/integration/
  test_pipeline_t1.py    # 用固定 ASR 产物（mock 模型）跑通 5 阶段
  test_resume.py         # 各阶段断点续跑
  test_time_invariant.py # 翻译前后时间码逐条相等
tests/eval/
  run_eval.py            # T1–T5 指标汇总，输出 Markdown 报告
```

- 单元测试**不加载真实模型**（用固定 JSONL fixture），保证 CI 秒级。
- 集成测试可 mock LLM 客户端，用固定响应验证编排逻辑。
- 真实模型与真实 LLM 的评测只在本地手动跑，不进 CI（成本与不确定性）。

## 6. 回归流程

1. 改 prompt / 模型 / 术语表 / 断句规则 →  bump `prompt_version` 或 `glossary_version`。
2. 跑 `pytest tests/unit tests/integration`（CI 门禁）。
3. 跑 `python tests/eval/run_eval.py --set T1..T5 --tag <version>`，产出 `out/eval/<tag>.md`。
4. 与上一版及 `tests/baseline/videolingo/` 对比，指标退化超过阈值则阻断合并。
5. 结论（含数据与阻塞）按项目规范单行追加到 `.agents/blackboard.md`。

## 7. A/B 记录模板

```markdown
## A/B <日期> <变更点>
- 版本：prompt v1 → v2 / 模型 X → Y / 术语表 v1 → v2
- 数据集：T1..T5（固定 20_cues.jsonl，不重跑 ASR）
- 指标：术语一致率 / 数字保留 / CPS / 人工评分 / token / 耗时
- 结果：<表格>
- 结论：采用 / 回滚 / 待观察
- 备注：缓存是否清空、是否影响已发布字幕
```

## 8. CI 检查项（M2 起）

- `ruff check` + `ruff format --check`
- `pytest tests/unit tests/integration`
- `cueloom validate` 对所有 fixtures JSONL / SRT
- 断言：无 `*.log`、无密钥、无大二进制进入提交
- 文档一致性检查：`03` 中的字段与 `models.py` 同步（可写脚本粗检）
