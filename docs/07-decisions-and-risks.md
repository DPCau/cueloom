# 07 · 决策记录（ADR）、命名核验与风险

## 1. ADR 索引

状态：`Accepted` 已定 / `Proposed` 建议待确认 / `Superseded` 被替代。变更决策时追加新 ADR，把旧条目标为 Superseded，不直接改写历史结论。

### ADR-001 · 自建薄编排层，而非整套部署开源 GUI 项目 — Accepted（2026-11-08）

- 背景：C-1 不配音、C-2 不烧录、C-3 自有 LLM。现成项目 60–80% 功能与依赖（TTS、yt-dlp、Streamlit、FFmpeg 烧录、全局 config）用不上；其 LLM 客户端是单任务同步调用，无法做并发/限流/按 cue 重试/缓存/成本归因。
- 决定：复用开源库（ASR、对齐、字幕格式）+ 自写约 1500–2500 行编排层；自写范围限定为断句、翻译编排、质检回填。
- 后果：换来可控性与可测试性；代价是要自己实现语义断句，并用 VideoLingo 作质量基线防退化。
- 推翻条件：若只是偶尔翻几段视频、不做服务化与二次集成，改用路线 A。

### ADR-002 · 范围严格限定为「只出字幕文件」 — Accepted（2026-11-08）→ 部分 Superseded（2026-11-08，ADR-010）

> 状态注记（2026-11-08）：仅「不实现 GUI」一项由 ADR-010 取代，允许零构建的只读运维看板；「只出字幕文件」等其余结论继续有效。以下为历史原文，未改写。

- 决定：不实现 TTS、配音、烧录、mux、yt-dlp、GUI、OCR、说话人分离、多租户。
- 后果：可去掉 FFmpeg 运行期依赖（faster-whisper + PyAV 路径）、去掉 CUDA/cuDNN 的部分约束、产物是纯文本便于 diff 与版本管理。

### ADR-003 · 时间码永不交给 LLM — Accepted（2026-11-08）

- 决定：LLM 只处理 `{id, text}`；`start/end` 仅由 Stage 2 写入；双语 = 同一 cue 两行。
- 后果：彻底消除 LLM 篡改时间码、生成伪 SRT 的风险；省 token；翻译前后时间码可做硬断言（见 `06`）。

### ADR-004 · 每阶段 JSONL 落盘 + cue.id 稳定 — Accepted（2026-11-08）

- 决定：五阶段产物落盘，支持 resume、单阶段 A/B、问题复现；cue.id 作为回填/缓存/质检主键。
- 后果：磁盘 I/O 与产物管理变复杂，但换来可调试性；这是自建相对 GUI 工具的核心收益之一。

### ADR-005 · ASR 双后端可切换，默认 faster-whisper — Accepted（2026-11-08，默认值待实测校准）

- 决定：`AsrBackend` Protocol；默认 faster-whisper（通用多语、内置 PyAV 解码），中文/方言场景可切 Qwen3-ASR 或 FunASR。对齐首选 Qwen3-ForcedAligner，备选 WhisperX。
- 后果：重型依赖放 extras，默认安装轻；需要在 T1/T2 测试集上实测后固定推荐默认值（见 D-02）。

### ADR-006 · CLI 优先，FastAPI 仅薄封装 — Accepted（2026-11-08）→ Superseded（2026-11-08，ADR-009 / ADR-010）

> 状态注记（2026-11-08）：服务层与看板提前到框架阶段；「路由只调用 `pipeline.run(job)`、不引队列 / 数据库」的结论继续有效。以下为历史原文，未改写。

- 决定：M1/M2 只做 CLI + Python API；M3 才加 FastAPI，且路由只调用 `pipeline.run(job)`。
- 后果：避免过早引入队列、数据库、鉴权；服务化成本后置但很低。

### ADR-007 · 项目命名 CueLoom — Proposed（待用户最终确认）

- 决定：仓库 / PyPI 包 / CLI / 镜像统一用 `cueloom`；中文副名可选「织幕」或「行间」。
- 依据：见 §2 命名核验；`cue` 是字幕标准术语，`loom` 表示原文/译文/时间轴交织，且不含 video/dub/voice/burn 等误导词、不绑定 SRT 单一格式。
- 后果：名字尚未被占用，但需尽快确认并注册；若用户改名，需全仓批量替换并更新本文档。

### ADR-008 · 开源许可证建议 Apache-2.0 — Proposed（待确认，D-01）

- 背景：项目会参考 Apache-2.0 的 VideoLingo / Qwen3-ASR 生态，但不复制其代码；若未来考虑商用集成，宽松许可更合适。
- 决定建议：Apache-2.0；若用户更看重极简，可用 MIT。GPL 不选（与自建目的冲突）。
- 后果：确认前**不要创建 LICENSE 文件**，也不要在 README 声称许可。

### ADR-009 · 单一交互式控制脚本 ctl.sh — Accepted（2026-11-08）→ 部分 Superseded（2026-11-09，ADR-014）

> 状态注记（2026-11-09）：仅「唯一人工入口」一句被取代——浏览器 Web 工作台成为默认业务操作面；`ctl.sh` 仍是**服务生命周期入口**与无浏览器时的兜底，纯数字菜单、不接复杂参数、PID/日志位置、服务可停止等结论继续有效。见 `12 §1` / `12 §4`。以下为历史原文，未改写。

- 背景：U-1 要求「一个脚本执行后通过输入选择开启 / 关闭 / 查看状态」，不接受复杂参数启动。
- 决定：仓库根 `ctl.sh` 作为唯一人工入口，纯数字菜单；本地模式管 PID 与日志，Docker 模式包一层 compose up/down；业务参数一律走 `.env` 与 `configs/`，不进命令行。
- 后果：上手成本降到「运行 + 输数字」；代价是 CI 自动化需另议（D-14）。PID 与日志放已忽略的 `work/ctl/`，服务必须可停止。

### ADR-010 · 浏览器运维看板（零构建、只读） — Accepted（2026-11-08）→ Superseded（2026-11-09，ADR-014）

> 状态注记（2026-11-09）：U-11 明确看板与工作台是同一个浏览器操作界面，「只读」与「单文件」两条由 ADR-014 取代；**零构建、无 npm / 前端框架 / CDN、只出字幕文件** 三条继续有效。以下为历史原文，未改写。

- 背景：U-2 要求前端为浏览器运行看板；原 N-4 / ADR-002 禁止 Web UI。
- 决定：允许一个由 FastAPI 托管的单文件原生 HTML 看板，只做状态 / 配置 / job / 产物观测；禁止 Streamlit、Gradio、桌面 GUI、npm / 前端框架与任何构建产物；ADR-002 中「不实现 GUI」一项由此取代，「只出字幕文件」不变。
- 后果：满足可观测性且不引入前端工具链与额外依赖；看板不承载业务逻辑，写操作留 M3（D-13）。
- 修订注记（2026-11-09）：U-9 要求模型下载 / 删除工作台。若采用 `10 §9` 方案 B，看板「只读」这一条将被局部放宽，结论以 D-16 为准；方案 A（控制台操作 + 看板只读展示）下本 ADR 完全不变。D-16 已于同日结清为方案 B，最终结论见 ADR-014。

### ADR-011 · Docker 部署与产物隔离 — Accepted（2026-11-08）

- 背景：U-5 可 Docker 部署；U-6 不把 Docker 产物放到本机里、测试后服务必须及时关闭。
- 决定：提交 Dockerfile / compose / .dockerignore 作为部署能力；运行产物用 Docker named volume，不 bind mount 项目目录；框架阶段不 build、不 up；任何实测后必须 down 并清理，本机项目目录不得留下镜像 / tar / 容器数据。
- 后果：部署能力可交付且不污染工作区；镜像发布时机登记为 D-12。
- 修订注记（2026-11-09）：其中「模型权重同样放 named volume、不 bind mount 项目目录」与 U-7 冲突，**该分句由 ADR-012 取代**；镜像 / 容器 / 构建缓存 / `work` / `out` 的产物隔离结论继续有效。

### ADR-012 · 模型资产放在项目内并用显式本地路径加载 — Accepted（2026-11-09，设计已定 / 代码待 M0.6）

- 背景：U-7 / U-8 要求模型权重与项目目录在一起、软件自动识别已有模型；原实现用 `WhisperModel("large-v3")`，权重会落到 `~/.cache/huggingface`，且 `09 §7` 把模型放进了 Docker named volume。
- 决定：`<root>/models/` 是唯一模型资产根；一个模型一个目录，由 `configs/model-catalog.yaml` 登记；流水线把**绝对本地目录路径**传给 `WhisperModel(..., local_files_only=True)`，利用其 `os.path.isdir` 分支完全绕开 Hub 下载与系统缓存；不使用 `download_root`、不运行时改写 `HF_HOME`。识别靠必需文件 + 体积下限 + LFS pointer 检测，不靠目录名。
- 后果：模型可见、可搬、可删、可复现；代价是权重不进镜像（靠 `./models` 挂载）、不进 git（R-13），且需修掉 `asr.py` 依赖缺失时静默降级为 Mock 的隐患。Docker 挂载方式由 D-17 定。

### ADR-013 · 模型管理属控制面，写操作不进数据面 — Accepted（2026-11-09）

- 背景：U-9 的下载 / 删除是写操作，而 `ADR-006` 要求服务层不写业务逻辑、`ADR-010` 要求看板只读。
- 决定：模型管理的写操作只作用于 `models/`，由独立的 `model_manager` 承接；不得触碰 `work/`、`out/`、`job.json`、`pipeline.run()`；浏览器写接口（方案 B）必须只监听回环地址，且二次确认与路径白名单不可省（见 `10 §8`）。
- 后果：新增能力不污染五阶段数据面，也不引入队列 / 数据库；代价是 `ctl.sh` 与看板若同时提供入口，必须共用同一 `model_manager`，避免两套口径。

### ADR-014 · 统一 Web 工作台为默认操作面 — Accepted（2026-11-09，设计已定 / 代码待 M0.7）

- 背景：U-11~U-13 明确「看板与工作台是同一个集成 Web 操作界面」，要在浏览器里发起工作流、改配置、管模型与 API；原 `ADR-009`「唯一人工入口 `ctl.sh`」、`ADR-010`「零构建只读看板」、`00` N-4「只读例外」、`D-13`/`D-16` 全部与之冲突。
- 决定：① 浏览器工作台是**默认业务操作面**，`ctl.sh` 退为服务生命周期入口与 CLI 兜底；② 看板与工作台合并为一个零构建多标签页静态站点（概览 / 运行 / 配置 / API / 模型 / 产物与日志），允许写接口；③ 前端可拆成 `index.html` + `app.js` + `style.css` 三个静态文件由 FastAPI 托管，但**仍禁止** npm / Node / Vite / React / Vue / CDN / 外链字体与任何构建产物；④ 新增命令层 `control/`，路由只做校验与序列化，所有写操作经命令层，`pipeline.run(job, cfg)` 仍是唯一业务入口；⑤ `D-13` 结清为「需要，提前到 M0.7」，`D-16` 结清为 `10 §9` **方案 B**（浏览器可写）。
- 后果：满足「一个界面完成全部操作」；代价是服务从只读变为可写，安全边界必须按 ADR-016 收紧，配置热更新须按 ADR-015 处理；`00 §2`「命令行优先」与 `02` P-5 需局部改写，但 CLI / Python API 仍可独立跑完整流水线。

### ADR-015 · 配置分层写入与 job 级快照 — Accepted（2026-11-09）

- 背景：浏览器要能改配置，而 `config.py` 用 `load_dotenv(override=False)`，`ctl.sh` 又全量 `source .env` 注入进程环境；只改文件会导致「写成功但不生效」。运行中任务若读到中途改动，结果不可复现。
- 决定：① `configs/default.yaml` 入库且**不可写**；② 非敏感业务参数写 `configs/local.yaml`，密钥与服务绑定写 `.env`，一个键只有一个写入目标；③ 写入走白名单 schema 校验、逐行 upsert（保留注释与未知键）、`tmp + os.replace` 原子替换、`.env` 权限 `0600`、写前备份；④ `ctl.sh` 停止全量 `source .env`（只解析 HOST/PORT/LOG_LEVEL），`server.py` 去掉模块级 `CFG` 改可刷新 `ConfigProvider`，写回后同步本进程白名单 `CUELOOM_*` 环境变量；⑤ **job 发起时冻结一份 `Config` 快照**并把 `config_digest` / `asr_model_id` 写进 `job.json`，配置改动只对下一次运行生效。
- 后果：改动即时可见且可复现；代价是需要实现配置提供器与测试覆盖注释、重复键、外部环境变量覆盖等边界。`/api/config` 的字段由服务端 schema 驱动，未接线的开关不得展示为可生效（R-24）。

### ADR-016 · 本地可写工作台的安全边界 — Accepted（2026-11-09）

- 背景：写接口能改 API 密钥、触发计费任务、删除 3 GB 模型、上传文件，风险远高于只读看板；`00` N-6 又规定一期不做账号 / 多租户鉴权，`D-11` 未结清。
- 决定：① 不做账号体系、不做多租户（N-6 不变），但补**单机最小防护**：非回环地址 + 启用写接口时 **fail-fast 拒绝启动**；② 所有非 GET 请求校验 `Host`/`Origin`，浏览器必须带自定义头 `X-Cueloom-Client: web`，不设置任何 CORS 允许头；③ 可选本地令牌（`work/ctl/web.token`，`0600`，`hmac.compare_digest`），强度由 D-19 定；④ 全部文件参数走 `safe_under()`（`resolve()` 包含校验 + 字符集白名单 + 拒绝符号链接逃逸），上传双重限额与后缀白名单，破坏性操作回传 id 二次确认且默认软删除；⑤ 写操作写 `work/ctl/audit.log`，不记密钥与字幕正文；⑥ 探活限流、流水线单飞、下载单飞。
- 后果：在不引入鉴权框架的前提下挡住跨站调用与路径穿越；代价是公网暴露被明确禁止（D-11 收窄为 D-19），容器模式配置写接口返回 `read_only_mode`（`12 §12`）。

### ADR-017 · 本机免登录、远端凭证访问与前端按职责拆分 — Accepted（2026-11-09，用户确认；代码待实现）

- 用户确认：D-19 本机自动通过，非本机输入 token，预留固定密码方式；D-23 允许前端合理拆分，不设三个文件上限。
- 替代 ADR-016 的「非回环直接拒绝启动」：默认仍绑定回环；用户显式开启远程模式时，必须配置强 token，否则拒绝启动。远程鉴权覆盖全部业务 GET 与写接口、日志、素材与字幕下载，仅最小健康检查、登录页及不含敏感数据的静态资源例外。固定密码登录接口预留，未设置密码时禁用，无内置默认密码。
- 本机免登录只依据实际 TCP 对端为回环地址；不依据 Host、Origin、私网 IP 或客户端声称自己是本机。Origin/Host/CSRF 检查继续执行，回环也不例外。默认不信任 X-Forwarded-For 等代理头；经代理或 Docker 转发无法可靠辨认来源时，保守要求鉴权，禁止为方便而把全部代理来源当本机。SSH 本地转发属于受信隧道，不承诺识别其原始远端。
- token 为随机高熵值，仅在 Authorization 头或受保护会话内传递，不放 URL/日志；比较使用恒定时间函数。固定密码只存加盐自适应哈希，登录限速、会话有过期与注销机制。非本机访问须通过 HTTPS 或 SSH 安全隧道，不以 token 代替传输加密。
- 前端按页面与职责合理拆分 HTML/CSS/原生 JS 模块，取消单文件与三个文件上限；仍维持零构建，无需 npm/框架/CDN。本次不额外禁止未来有理由引入的技术，届时另记 ADR。
- D-20 于 2026-11-09 19:39 用户确认选择方案 A：浏览器选择音视频并上传到项目内 `inbox/` 后处理；不提供服务端授权目录浏览或任意绝对路径输入。内置 demo 只作测试演示入口，CLI 的本地路径能力不因此取消。上传需要大小限制、临时文件原子转正、服务端生成素材 id 与原始文件名分离、鉴权及路径校验；同名素材不得静默覆盖。

## 3. 风险登记
